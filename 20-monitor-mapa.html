Metrics · Logs · Insights

No son tres servicios distintos: son tres capas dentro de Azure Monitor. Insights no compite con Metrics/Logs — los consume.

Metrics
Números en el tiempo. Livianos, casi instantáneos, pensados para "¿cómo va esto ahora mismo?"
FormatoSerie temporal numérica
LatenciaSegundos
Ejemplo% CPU, IOPS, bytes/seg
1
Metrics Explorer — el número llega casi al instante y lo ves como gráfico, sin necesidad de guardarlo antes
2
Metric Alert — definís un umbral directo sobre ese número (ej. CPU > 80%) y te avisa apenas lo cruza, sin pasar por ninguna query
Logs
Registros con contexto. Más pesados, con delay, pensados para "¿qué pasó exactamente y por qué?"
FormatoFilas estructuradas / texto
LatenciaMinutos
EjemploExcepción, evento de auditoría
1
Log Analytics Workspace — los logs crudos llegan acá. Plan Analytics vs Basic/Auxiliary; Archive hasta 12 años = search job
2
KQL — es el lenguaje que usás para consultar esos logs (ej. "dame todos los errores de la última hora")
3
Log Alert — tomás esa misma query KQL y la convertís en una regla de alerta, para que te avise solo cuando el resultado cumpla una condición
"Insights" = soluciones curadas
Un Insight no es un tercer tipo de dato — es un producto terminado que combina Metrics + Logs + visualización lista para un dominio específico, para que no tengas que armar el dashboard vos mismo.

La diferenciación en una frase

Metrics y Logs son los dos tipos de dato crudo que existen dentro de Azure Monitor.

Insights (App / VM / Container) son soluciones prearmadas que leen esos dos tipos de dato y te los presentan con contexto, para un dominio puntual, sin que tengas que configurar nada desde cero.

Por eso Application Insights no reemplaza a Log Analytics: Application Insights → guarda todo en → Log Analytics Workspace. Es consumidor, no competidor.
