⚠️ Por qué hay prioridades marcadas

Este set se contrastó bullet por bullet contra el skills outline oficial. Varios servicios que históricamente se estudiaban para el AZ-104 ya no figuran entre los skills measured: AKS, Application Gateway, WAF, Front Door, Traffic Manager, VPN Gateway, ExpressRoute, Virtual WAN y Azure Firewall.

El material sigue acá porque una pregunta de escenario los puede nombrar como distractores y conviene reconocerlos — pero es tiempo de estudio con menor retorno. Priorizá lo marcado como núcleo.

■ Núcleo
Todo el módulo mapea a bullets del outline vigente. Acá se juega el examen.
■ Mixto
Parte del módulo es núcleo y parte quedó fuera del outline. La nota amarilla te dice qué es cada cosa.
■ Contexto
Ningún bullet del outline lo pide. Lectura de reconocimiento, al final y sin memorizar.

Storage Accounts
Tipos de cuenta, Standard vs Premium (FileStorage se crea, no se convierte desde GPv1/GPv2; solo una región = ZRS, no GRS/GZRS), CLI create = StorageV2 + Standard_GRS (tiers+lifecycle+geo, no RA-GRS/GZRS), access tiers (30/90/180; sin Cold en el drop-down + inmediato = Cool, no Archive), redundancia (Files NFSv4.1 LRS→ZRS = migración manual), failover y endpoints.

Storage · Seguridad y acceso
Los tres tipos de SAS (ad hoc = Explorer → container → upload → SAS en el token, no stored policy ni RG; start time ≠ now por clock skew; Yes/No/Yes/Yes), stored access policies, access keys (CLI: [1].value → renew primary → [0].value → renew secondary), CMK, RBAC de plano de datos, Storage Explorer (List/Get SAs = Reader en la sub), firewall (endpoint Microsoft.Storage + Add-AzStorageAccountNetworkRule + -Bypass AzureServices para vault/Event Hub), endpoints y cifrado.

Virtual Machines

App Service

12-vnets-dns.htmlNúcleo
VNets, IPs y DNS
Las 5 IPs reservadas, Public IP (HTTP 80 + dash en NIC Public IP = primero asociar PIP a ipconfig1, no JIT/NSG/accelerated), address space (172.16→192.168 sin VMs = borrar y recrear; add no saca el rango viejo), peering (no transitivo; Use remote en la spoke + peering para usar el ER del hub, no gateway extra; si el enunciado lista un solo lado no asumas el recíproco: vnet1→vnet2 only, vnet2→vnet3 only), endpoints (PLS = privateLinkServiceNetworkPolicies Disabled: Yes/Yes/No, el No es ACL), DNS (A alias sigue el ciclo de vida de otro A; CNAME/A común no).

13-seguridad-de-red.htmlMixto
Seguridad de red
Prioridades y reglas por defecto de NSG (restricción de una VM = NIC, no subnet; tres CIDR exactos = una regla con lista separada por comas, no supernet /22 ni VirtualNetwork ni tres reglas), ASG, Bastion (policy sin 22/3389 = Bastion, no S2S/P2S ni NSG Allow RDP; orden = AzureBastionSubnet /26 → crear Bastion → portal, no PIP en la VM ni BastionSubnet), UDR (NVA = route table + bind a subnets de workload, no NIC/ILB/NSG) y forced tunneling.

16-azure-monitor.htmlNúcleo
Azure Monitor
Metrics vs Logs vs Insights (Storage Insights: sort Transactions = unused; Overview no es 500, es 200; coloring de Availability sí), Diagnostic Settings (query universal = LAW primero, no NW/MMA/diag settings; IoT Hub telemetry + alertas = resource logs del hub, no App Insights/Resource Health/Activity Log), AMA y DCR, guest OS = Set-AzVMDiagnosticsExtension -DiagnosticsConfigurationPath (no BootDiagnostics), LAW, KQL, pin a dashboard = 30 días (no 4×7 ni solo line/column), alertas (az monitor metrics alert create --condition --window-size --action), metrics:getBatch (un POST evita throttling; host regional = no varias regiones; metricNamespace = mismo tipo), Network Watcher (HTTPS peering = Connection Troubleshoot TCP primero, no agente en origen/NPM/ping; packet capture 2 h = NW, no Monitor/PerfMon/NPM; Topology, IP Flow, probes, Flow logs).

17-backup-site-recovery.htmlNúcleo
Backup y Site Recovery
RPO vs RTO, RSV vs Backup vault, mínimo de vaults = regiones (no OS), redundancia LRS/GRS al crear + soft delete 14 días (no “solo VMs”, no un vault cross-sub), mover vault = Move-AzResource (no Export-/New-), borrar vault = stop backup + disable soft delete + purge (no borrar las VMs ni la policy), CRR paired region, default daily = 30 días, policy exhibit = max retention el más largo (monthly 24 months) y RPO = frecuencia (1 day, no Instant Restore), primer backup = Register → New vault → Enable-…Protection (no Backup-Item ni AutoProtection), MARS vs MABS, GFS, restore/ILR, Pre-Check Warning = VM agent viejo, reportes (diag del vault → LAW, no blob/Event Hub/files), ASR (High Churn cache = Premium block blob, no GPv2/Files/Elastic SAN; planned failover = test + shutdown + commit; unplanned = RPO).

Fase 5 — Llevarlo a la práctica

18 cubre las trampas del material sin gastar la suscripción. 19 es para clicar Azure de verdad. No mezcles: primero el escenario, después el lab del mismo tema.

Cómo usar cada módulo

  1. Primera pasada — leer. Recorré el módulo entero con la barra lateral. No pares en las flashcards todavía; el objetivo es armar el mapa mental y las distinciones.
  2. Segunda pasada — cazar trampas. Volvé y leé solo los callouts amarillos de «Trampa del examen». Ahí está concentrado casi todo lo que te hace fallar una pregunta que creías saber.
  3. Tercera pasada — flashcards. Corré la ronda completa. Todo lo que caiga en «a repasar» al final volvé a buscarlo en la sección correspondiente, no lo memorices suelto.
  4. Cuarta pasada — escenarios. En 18 · Ejercicios resolvés cada caso sin mirar la solución. Recién después la abrís. Lo que falles, volvé al módulo.
  5. En el portal. 19 · Labs es para clicar Azure de verdad. No reemplaza a los escenarios.
  6. Antes del examen. Solo las tablas comparativas, las flashcards que fallaste y los escenarios de 18 que marcaste mal. Nada de contenido nuevo.
