Árbol de decisión rápido

¿El tráfico es HTTP/HTTPS?
No (TCP/UDP genérico) → Load Balancer
Sí → seguir
¿Necesitas enrutamiento por contenido (path/host) dentro de una región?
Sí, solo una región → Application Gateway (+ WAF_v2 si necesitas firewall)
Sí, multi-región / global → seguir
¿Necesitas CDN + seguridad + balanceo global en un solo servicio?
Sí → Front Door (Premium incluye WAF integrado)
No, solo necesitas resolver DNS al endpoint más cercano/sano, incluso fuera de Azure → Traffic Manager

Detalle por servicio

Azure Load Balancer
  • Público o Interno (ILB): expone servicio externamente o solo dentro de la VNet.
  • SKU Standard: soporta Zonas de disponibilidad, requiere NSG explícito (no abre tráfico por defecto).
  • No entiende HTTP: no puede hacer cookie-based affinity a nivel de sesión de aplicación (solo 5-tuple hash o session persistence por IP de cliente).
  • Usado detrás de VMSS para distribuir carga entre instancias.
Application Gateway
  • Requiere su propia subnet dedicada dentro de la VNet.
  • v2 soporta autoscaling y zone redundancy; la v1 no.
  • Funciones clave: path-based routing, multi-site hosting (varios dominios en un mismo gateway), rewrite HTTP headers/URL, redirect.
  • WAF_v2 añade el firewall (OWASP Core Rule Set) en modo Detección o Prevención.
WAF (Web Application Firewall)
  • No es un servicio standalone independiente para desplegar solo: viene integrado en Application Gateway o en Front Door Premium.
  • Modos: Detection (solo loguea) y Prevention (bloquea).
  • Usa Core Rule Set (CRS) de OWASP; se pueden crear reglas custom.
Azure Front Door
  • Es Anycast: el usuario llega al POP más cercano de Microsoft, luego el tráfico viaja por la red backbone de Microsoft hasta el origen.
  • Combina: balanceo global L7, CDN, WAF (Premium), aceleración TLS.
  • Reemplaza al antiguo "Azure Front Door (classic)"; el modelo actual usa perfiles, endpoints, origin groups y reglas de enrutamiento.
  • Trampa de examen: no confundir con Traffic Manager — Front Door sí procesa el tráfico HTTP; Traffic Manager solo resuelve DNS.
Traffic Manager
  • Es puramente DNS-based: el cliente resuelve un nombre y Traffic Manager le da la IP del endpoint elegido; después el cliente se conecta directo, sin pasar por Azure.
  • Métodos de enrutamiento: Priority, Weighted, Performance, Geographic, MultiValue, Subnet.
  • Puede apuntar a endpoints fuera de Azure (on-premises, otras nubes).
  • Como no ve el tráfico real, no ofrece SSL offload ni WAF.
Trampas comunes del examen:
  • Load Balancer NO entiende contenido HTTP → si la pregunta menciona "enrutar por URL/path", la respuesta nunca es Load Balancer.
  • Traffic Manager NO balancea tráfico real, solo resuelve DNS → no ofrece terminación SSL ni WAF.
  • WAF no se despliega solo: siempre va dentro de Application Gateway (WAF_v2) o Front Door (Premium).
  • Front Door es global/anycast; Application Gateway es regional. Si la pregunta requiere multi-región con un solo punto de entrada → Front Door, no App Gateway.
  • Application Gateway necesita una subnet dedicada — no puede compartir subnet con otros recursos.
